# Aplicación de Solución IA bajo SDD (Spec Driven Development)

El objetivo principal de este proyecto es construir y desplegar una aplicación funcional (la que ustedes elijan) de principio a fin (Frontend, Backend, Base de Datos y DevOps/Ciberseguridad) utilizando la metodología de Spec-Driven Development (SDD).

El proyecto demuestra el valor, la velocidad y la rigurosidad de desarrollar software estructurado con especificaciones e Inteligencia Artificial en comparación con los métodos tradicionales o la generación de código a través de prompts sencillos.

## 🏗️ Requisitos Técnicos y de Arquitectura

**Aplicación Completa:** Debe seleccionarse una aplicación a elección del equipo (por ejemplo, una herramienta de observabilidad de servidores o un sistema de apuestas).

### Componentes Requeridos:

- Frontend: Interfaz visual totalmente integrada.
- Backend / APIs: Lógica de negocio y servicios.
- Base de Datos: Persistencia de datos configurada.
- Herramientas de SDD: Implementación del código utilizando herramientas como Spec Kit (preferido de GitHub) u OpenSpec.
- Despliegue (DevOps) y Hosting: Publicación en un entorno totalmente integrado y gratuito (ej. Vercel, Railway, etc.).
- Ciberseguridad y Calidad: Inclusión de pruebas automatizadas y prácticas de seguridad en el código para prevenir vulnerabilidades y gestionar el riesgo.

## 👥 Dinámica de Trabajo y Evaluación del Entregable

La entrega del proyecto consta de dos fases:

1. Línea Base (Línea Inicial del Producto)
El equipo construirá una aplicación inicial basada en un backlog priorizado.
En la demostración presencial se presentarán aproximadamente 10 Historias de Usuario (HU) previamente desarrolladas y desplegadas.

2. Demostración en Vivo (In-Situ)
Durante la presentación, el profesor asignará la construcción en vivo de dos nuevas Historias de Usuario.
- Trabajo Individual/Colaborativo: Cada integrante del equipo deberá ejecutar el motor de SDD desde su máquina para implementar tickets/subtareas específicas asignadas en vivo.
- Continuidad e Incremento: La aplicación se construirá incrementalmente. Las historias desarrolladas en vivo deben tener coherencia técnica y lógica con la línea base.
- Publicación: Al finalizar (en un estimado de 5 a 10 minutos por spec), se ejecutará y mostrará la aplicación actualizada y desplegada.

## 📊 Caso de Negocio y Comparativa de Costos

Como componente complementario, se incluirá un caso de negocio sintético:
Costos de Infraestructura e IA: Control y optimización del gasto (aprovechando licenciamientos estudiantiles como GitHub Copilot o modelos de capa gratuita para servidores).
Análisis Comparativo: Evaluación del ROI y tiempo/costo (OPEX / CAPEX) al desarrollar mediante Spec-Driven Development en contraste con el desarrollo a la "antigüita" o mediante prompts tradicionales.
